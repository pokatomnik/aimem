# Сделать Web UI

## Описание

Web UI должен работать на том же самом порту что и Web сервер проекта. UI поисковика будет использовать endpoint'ы, описанные в [openapi.yaml](internal/controllers/web/openapi.yaml)

## Технологии

- React
- Typescript
- Vite
- Vitest
- Стили (о них ниже)

## Сборка Web UI

Сборка Web UI должна запускаться с помощью `npm run build`.
Сборку ОБЯЗАТЕЛЬНО нужно встроить в имеющийся Makefile как часть процесса сборки.

Исходный код веб части нужно разместить тут: internal/controllers/web/ui

Сборка должна быть в internal/controllers/web/ui/dist

Важный момент: все что попадет в dist будет подключаться бекендом на golang с помощью пакета `embed`. Учти это.

То есть:

- Сборка веб части
- Сборка backend на Golang

Файлы проекта на go пока что не трогай. Пиши только frontend

## Внешний вид

Требований по стилю особых нет, но лучше ориентироваться на лучшие практики современного дизайна поисковых систем. Удели внимание внешнему виду, это важно, то есть верстай чтобы было субьективно симпатично. Если будут проблемы, то внешний вид доверстаем чуть позже, главное собрать прототип.

Для стилизации можешь верстать сам или можешь использовать какую-нибудь готовую библиотеку, главное чтобы не приходилось библиотечные компоненты сильно кастомизировать.

Можешь использовать styled-components, css modules, scss, sass, css на твой выбор, требований нет

Мое пожелание по цветам: основные цвета должны быть такие:

- оранжевый
- черный (все тексты)
- серый (secondary texts)

## Маршрутизация

Базовый маршрут по которому будет отдаваться html этого SPA - `/`.

Должна быть реализована маршрутизация с помощью React Router. Маршрутизация должна делаться с помощью HashRouter, а не HTML5 router. Это упрочстит настроку сервера.
Маршруты:

- `/` (главная страница, ввод поискового запроса). Сделать стоит примерно так же как и у других поисковых систем: поле ввода по центру, когда пользователь нажал на кнопку поиска (добавь emoji лупу в качестве подписи у кнопки) нужно сразу сделать переход на `/search` (см ниже). Live поиск (поиск по мере печати) НЕ надо делать: сервер не осилит такой нагрузки. Debounce не нужен, поиск ТОЛЬКО по нажатию.
- `/search?q=запрос+пользователя` (такой формат запроса должен соблюдаться). Здесь по аналогии с другими поисковыми системами: результаты поиска, сверху - поле ввода. В результатах поиска только ID факта + summary которое есть.
- `/fact/{factID}` - страница факта. Рендерить стоит как Markdown, но нужно предусмотреть кнопку "назад": кнопка будет навигировать пользователя на главную страницу. Здесь же должна быть кнопка "Удалить", которая будет удалять факт. Метода для удаления пока что нет, но он появится, оставь пока кнопку, но предусмотри что она также будет работать с http клиентом
- `/fact/add` - форма ввода для новых знаний. По факту - простой текстовый редактор, можно не делать визуальный редактор Markdown для упрощения.

## HTTP клиент

HTTP клиент должен генерироваться из файла openapi.yaml. Скрипт генерации должен быть в package.json. В качестве транспорта нужно использовать fetch (никаких axios!). Файл openapi.yaml не должен перемещаться, пускай остается на своем месте где находится сейчас.

## Требования к коду

- Все пакеты должны иметь актуальную на момент написания версию. Стоит брать последние версии пакетов, но нужно следить за их совместимостью друг с другом.
- Надо разделять логику и UI: можно использовать state manager'ы но не обязательно, прими решение нужны ли они
- На код енужно писать тесты, особенно на бизнес логику. Правила написания тестов частично применимы из документа AGENTS.md: нельзя использовать side effects: никакого IO не должно быть в тестах.
- Настрой линтинг для проверок: `npm run test` + `npm run lint`, правила линтинга не критичны, но правила для typescript - да: использование `any` запрещено, включаем strict mode и запрещаем все по максимуму чтобы была очень строгая типизация.
- Архитектура: минимум связи между модулями, либо Feature Slice Design или Clean Architecture, выбирай, главное чтобы архитектура наследовала основные концепции DRY, SOLID и KISS.
